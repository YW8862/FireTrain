# 角色切换机制说明

## 概述

本系统采用了**纯前端视图角色切换**机制，允许管理员在不修改数据库的情况下，临时切换到普通用户视图。这种设计避免了频繁的数据库操作，提高了切换速度和用户体验。

## 核心概念

### 1. 两种角色的区别

- **数据库角色（真实角色）**：存储在数据库中，是用户的永久身份标识
  - 位置：`users.role` 字段
  - 用途：后端API权限验证、JWT Token生成
  
- **视图角色（有效角色）**：存储在前端，是用户当前看到的界面角色
  - 位置：前端 Pinia Store (`viewRole`)
  - 用途：前端路由控制、UI显示、菜单展示

### 2. effectiveRole（有效角色）

```javascript
// 计算属性：优先使用视图角色，否则使用数据库角色
const effectiveRole = computed(() => {
  return viewRole.value || userInfo.value?.role
})
```

## 工作流程

### 管理员切换到用户模式

1. **用户点击"切换到用户模式"**
   ```javascript
   // AdminLayout.vue
   const handleSwitchRole = async () => {
     const success = userStore.switchViewRole('user')
     if (success) {
       router.push('/')  // 跳转到用户首页
     }
   }
   ```

2. **前端更新状态**
   - `viewRole` 设置为 `'user'`
   - `localStorage.view_role` 设置为 `'user'`
   - **不修改数据库**
   - **不调用后端API**

3. **UI自动更新**
   - 导航栏显示"普通用户"标签
   - 隐藏管理员专属菜单
   - 显示"切换回管理员模式"按钮

4. **路由守卫检查**
   ```javascript
   // 使用 effectiveRole 进行权限判断
   if (to.meta.requiresRole.includes(userStore.effectiveRole)) {
     // 允许访问
   }
   ```

### 切换回管理员模式

1. **用户点击"切换回管理员模式"**
   ```javascript
   // NavBar.vue
   const handleSwitchBackToAdmin = () => {
     userStore.setViewRole(null)  // 清除视图角色
     router.push('/admin/dashboard')
   }
   ```

2. **前端恢复状态**
   - `viewRole` 设置为 `null`
   - `localStorage.view_role` 被删除
   - `effectiveRole` 自动恢复为数据库中的真实角色

3. **UI恢复**
   - 导航栏显示"管理员"或"Root"标签
   - 显示管理员专属菜单
   - 隐藏"切换回管理员模式"按钮

## 技术实现

### 1. Pinia Store (user.js)

```javascript
export const useUserStore = defineStore('user', () => {
  const token = ref(localStorage.getItem('token') || '')
  const userInfo = ref(null)
  const viewRole = ref(localStorage.getItem('view_role') || null)
  
  // 有效角色（用于权限判断）
  const effectiveRole = computed(() => {
    return viewRole.value || userInfo.value?.role
  })
  
  // 是否可以切换角色
  const canSwitchRole = computed(() => {
    return userInfo.value?.can_switch_role === true
  })
  
  // 设置视图角色
  function setViewRole(role) {
    viewRole.value = role
    if (role) {
      localStorage.setItem('view_role', role)
    } else {
      localStorage.removeItem('view_role')
    }
  }
  
  // 切换视图角色
  function switchViewRole(role) {
    if (canSwitchRole.value) {
      setViewRole(role)
      return true
    }
    return false
  }
})
```

### 2. 路由守卫 (router/index.js)

```javascript
router.beforeEach((to, _from) => {
  // ... 登录检查 ...
  
  // 检查角色权限（基于视图角色）
  if (to.meta.requiresRole && token) {
    const userStore = useUserStore()
    
    // 如果 userStore 已初始化，使用 effectiveRole
    let userRole
    if (userStore.userInfo) {
      userRole = userStore.effectiveRole
    } else {
      // 否则从 token 中解析（fallback）
      const payload = JSON.parse(atob(token.split('.')[1]))
      userRole = payload.role || 'user'
    }
    
    if (!to.meta.requiresRole.includes(userRole)) {
      return '/'  // 权限不足
    }
  }
})
```

### 3. UI组件

#### AdminLayout.vue
```vue
<template>
  <!-- 显示有效角色 -->
  <el-tag :type="getRoleType(userStore.effectiveRole)">
    {{ getRoleLabel(userStore.effectiveRole) }}
  </el-tag>
  
  <!-- 仅 Root 可见（基于有效角色） -->
  <el-menu-item v-if="userStore.effectiveRole === 'root'">
    管理员管理
  </el-menu-item>
</template>
```

#### NavBar.vue
```vue
<template>
  <!-- 是否为管理员（基于有效角色） -->
  <el-dropdown-item v-if="isAdmin" command="admin">
    管理后台
  </el-dropdown-item>
  
  <!-- 显示切换回管理员选项 -->
  <el-dropdown-item v-if="canSwitchBack" command="switch-back">
    切换回管理员模式
  </el-dropdown-item>
</template>

<script setup>
const isAdmin = computed(() => {
  return ['admin', 'root'].includes(userStore.effectiveRole)
})

const canSwitchBack = computed(() => {
  return userStore.viewRole === 'user' && 
         ['admin', 'root'].includes(userStore.userInfo?.role)
})
</script>
```

## 优势

### 1. 性能优势
- ✅ **零数据库操作**：切换时不需要更新数据库
- ✅ **零网络请求**：纯前端操作，响应速度快
- ✅ **无并发问题**：不涉及数据库事务和锁

### 2. 用户体验
- ✅ **即时切换**：无需等待服务器响应
- ✅ **状态持久化**：刷新页面后仍保持视图角色
- ✅ **简单直观**：用户理解成本低

### 3. 安全性
- ✅ **后端权限不变**：Token中的角色保持不变，后端API仍然安全
- ✅ **双重验证**：前端路由守卫 + 后端API验证
- ✅ **可追溯**：所有API调用都使用原始Token，便于审计

### 4. 灵活性
- ✅ **多标签页支持**：每个标签页可以独立设置视图角色
- ✅ **易于扩展**：可以轻松添加更多视图模式
- ✅ **解耦设计**：前端显示与后端权限分离

## 注意事项

### 1. 后端API权限

虽然后端仍然使用Token中的角色进行权限验证，但由于管理员的Token中包含`can_switch_role=true`，所以：

- 管理员切换到用户视图后，**仍然可以调用管理员API**（因为Token中的角色未变）
- 这是一种**信任模型**：我们信任管理员不会滥用权限
- 如果需要更严格的控制，可以在后端添加额外的验证逻辑

### 2. 数据一致性

- `viewRole` 只影响**前端显示和路由**
- 所有**数据操作**仍然使用原始角色的权限
- 例如：管理员即使用户视图，仍然可以看到所有用户的训练记录

### 3. 刷新页面

- 刷新页面后，`viewRole` 会从 `localStorage` 恢复
- 但 `userInfo` 需要重新获取（通过 `fetchUserInfo()`）
- 建议在应用启动时调用 `fetchUserInfo()`

## 未来改进方向

### 1. 真正的多角色支持

如果需要支持用户同时拥有多个角色（如既是管理员又是教练），可以：

```javascript
// 在 userInfo 中添加 availableRoles
userInfo: {
  username: 'admin',
  role: 'admin',  // 主要角色
  availableRoles: ['admin', 'coach', 'user'],  // 所有可用角色
  can_switch_role: true
}

// 切换时从 availableRoles 中选择
function switchViewRole(role) {
  if (userInfo.value?.availableRoles?.includes(role)) {
    setViewRole(role)
  }
}
```

### 2. 会话级角色切换

如果需要服务端状态管理，可以使用Session：

```python
@router.post("/switch-role")
async def switch_role(
    role_data: RoleSwitchRequest,
    session: Session = Depends(get_session)
):
    # 只在session中保存，不修改数据库
    session["current_view_role"] = role_data.target_role
    return {"message": "切换成功"}
```

### 3. 角色切换日志

记录角色切换操作，便于审计：

```javascript
// 切换时记录日志
function switchViewRole(role) {
  console.log(`[${new Date().toISOString()}] 角色切换: ${effectiveRole.value} -> ${role}`)
  // 可以发送到后端日志服务
  setViewRole(role)
}
```

## 总结

当前的纯前端视图角色切换机制是一个**简单、高效、安全**的解决方案，特别适合以下场景：

- ✅ 管理员需要临时查看用户视角
- ✅ 不需要严格的角色隔离
- ✅ 追求快速响应和良好用户体验

如果未来需要更复杂的角色管理（如多角色、细粒度权限控制），可以考虑升级到基于Session或JWT多角色的方案。
