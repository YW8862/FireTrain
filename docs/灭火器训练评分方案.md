# 灭火器训练评分方案

## 目标
- 统一 YOLO、MediaPipe、规则评分、LLM 增强和前端报告页的字段契约。
- 让系统先稳定识别“学员在做哪一步”，再基于统一摘要做规则评分和 LLM 增强。
- 保证在 LLM 不可用时，仍然能输出完整、可解释、可展示的评分结果。

## 训练步骤
1. `准备阶段`
2. `提灭火器`
3. `拔保险销`
4. `握喷管`
5. `瞄准火源`
6. `压把手`

## 评分维度
- `动作完整性`：40%
- `姿态规范性`：40%
- `操作时效性`：20%

## 步骤权重
- `准备阶段`：15%
- `提灭火器`：20%
- `拔保险销`：15%
- `握喷管`：15%
- `瞄准火源`：20%
- `压把手`：15%

## 核心识别信号
- YOLO 输出 `fire_extinguisher` 的出现帧数、检测次数、平均置信度。
- MediaPipe 输出 `right_arm`、`left_arm`、`body` 等角度统计。
- 逐帧抽取统一特征：
  - `extinguisher_detected`
  - `pose_available`
  - `arm_bent`
  - `arm_extended`
  - `arm_asymmetry`
  - `stable_body`
  - `nozzle_control_posture`
  - `aiming_posture`

## 统一摘要字段
推理服务输出 `analysis_summary`，核心字段包括：
- `detection_stats`
- `pose_stats_summary`
- `step_sequence`
- `step_times`
- `step_feature_summary`
- `completed_steps`
- `missing_steps`
- `validity_checks`

## 规则评分说明
- 规则引擎直接消费 `analysis_summary`。
- 每个步骤根据以下因素评分：
  - 步骤是否完成
  - 识别置信度
  - 姿态质量
  - 灭火器可见度
  - 步骤时长是否落在标准范围
- 输出统一结构：
  - `total_score`
  - `performance_level`
  - `performance_label`
  - `dimension_scores`
  - `step_scores`
  - `feedback`
  - `suggestions`

## LLM 增强说明
- LLM 与规则引擎共用同一份 `analysis_summary`。
- 规则引擎结果作为 `baseline_score` 传给 LLM。
- LLM 负责增强：
  - 自然语言整体评价
  - 更细粒度的步骤反馈
  - 更贴近教学语境的改进建议
- 当 LLM 不可用时，系统直接回退到规则评分。

## 持久化结构
评分结果持久化到训练记录的固定字段中：
- `total_score`
- `feedback`
- `step_scores`

其中 `step_scores` 额外保存元数据：
- `_suggestions`
- `_dimension_scores`
- `_performance_level`
- `_performance_label`
- `_score_source`
- `_analysis_summary`

## 前端展示契约
- 报告页优先读取详情接口显式字段：
  - `suggestions`
  - `dimension_scores`
  - `performance_level`
  - `performance_label`
  - `analysis_summary`
- 不再使用拍脑袋的维度分兜底逻辑伪造雷达图数据。

## 当前实现原则
- 先保证契约统一和链路打通。
- 识别规则采用可解释的时序启发式，方便后续继续调阈值。
- 如果后续引入更多检测类别或关键点特征，只需要继续扩展 `analysis_summary` 和步骤规则即可。
