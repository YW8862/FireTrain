# FireTrain 项目数据库表结构文档

## 概述

本文档详细描述了 FireTrain 灭火器实操测评系统的数据库表结构设计。系统采用 SQLAlchemy ORM 框架，使用异步模式进行数据库操作。

---

## 数据库表清单

1. **users** - 用户表
2. **training_records** - 训练记录表
3. **action_logs** - 动作日志表
4. **training_statistics** - 训练统计表
5. **admin_logs** - 管理员操作日志表
6. **video_detection_tasks** - 视频检测任务表

---

## 1. users 表（用户表）

存储系统所有用户信息，包括学生和管理员。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key | - | 用户ID，自增主键 |
| username | String(50) | Unique, Not Null | - | 用户名，唯一标识 |
| email | String(100) | Unique, Not Null | - | 邮箱地址，唯一标识 |
| password_hash | String(255) | Not Null | - | 密码哈希值（bcrypt加密） |
| phone | String(20) | Nullable | NULL | 电话号码（可选） |
| role | String(20) | Not Null | "student" | 用户角色：student/admin |
| is_active | Boolean | Not Null | True | 账号是否激活 |
| last_login_at | DateTime(timezone=True) | Nullable | NULL | 最后登录时间 |
| can_switch_role | Boolean | Nullable | False | 是否允许角色切换 |
| original_role | String(20) | Nullable | NULL | 原始角色（用于角色切换功能） |
| created_at | DateTime | Auto-generated | NOW() | 创建时间 |
| updated_at | DateTime | Auto-updated | NOW() | 更新时间 |

### 关系

- **一对多**: training_records（训练记录）
- **一对一**: training_statistics（训练统计）
- **一对多**: admin_logs（管理员操作日志，作为管理员时）
- **一对多**: video_detection_tasks（视频检测任务，作为上传者时）

### 索引

- `username` - 唯一索引
- `email` - 唯一索引

---

## 2. training_records 表（训练记录表）

存储每次训练的完整记录，包括评分、视频路径和反馈信息。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key | - | 记录ID，自增主键 |
| user_id | Integer | FK(users.id), Index, Not Null | - | 关联用户ID |
| training_type | String(50) | Not Null | - | 训练类型（如：extinguisher_use） |
| status | String(20) | Not Null | "completed" | 状态：completed/failed/in_progress |
| total_score | Numeric(5,2) | Not Null | 0.00 | 总分（0-100） |
| step_scores | JSON | Nullable | NULL | 各步骤得分详情（JSON格式） |
| video_path | String(255) | Nullable | NULL | 训练视频文件路径 |
| duration_seconds | Numeric(8,2) | Nullable | NULL | 训练持续时间（秒） |
| started_at | DateTime(timezone=True) | Nullable | NULL | 训练开始时间 |
| completed_at | DateTime(timezone=True) | Nullable | NULL | 训练完成时间 |
| feedback | Text | Nullable | NULL | AI生成的反馈文本 |
| created_at | DateTime | Auto-generated | NOW() | 创建时间 |
| updated_at | DateTime | Auto-updated | NOW() | 更新时间 |

### 关系

- **多对一**: user（所属用户）
- **一对多**: action_logs（动作日志）

### 索引

- `user_id` - 普通索引，加速用户训练记录查询
- 外键约束：`ondelete="CASCADE"`（用户删除时级联删除训练记录）

---

## 3. action_logs 表（动作日志表）

存储训练过程中每个动作的详细识别记录，用于细粒度分析。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key | - | 日志ID，自增主键 |
| record_id | Integer | FK(training_records.id), Index, Not Null | - | 关联训练记录ID |
| action_name | String(50) | Not Null | - | 动作名称（如：pull_pin, aim_nozzle） |
| step_index | SmallInteger | Not Null | - | 步骤序号 |
| is_correct | Boolean | Not Null | - | 动作是否正确 |
| confidence_score | Numeric(5,4) | Nullable | NULL | AI置信度分数（0-1） |
| action_timestamp | DateTime(timezone=True) | Not Null | - | 动作发生时间戳 |
| detail | JSON | Nullable | NULL | 动作详细信息（JSON格式） |

### 关系

- **多对一**: training_record（所属训练记录）

### 索引

- `record_id` - 普通索引，加速训练记录的动作日志查询
- 外键约束：`ondelete="CASCADE"`（训练记录删除时级联删除动作日志）

---

## 4. training_statistics 表（训练统计表）

存储用户的训练统计数据，用于快速展示用户学习进度。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key | - | 统计ID，自增主键 |
| user_id | Integer | FK(users.id), Unique, Not Null | - | 关联用户ID（一对一） |
| total_trainings | Integer | Not Null | 0 | 总训练次数 |
| completed_trainings | Integer | Not Null | 0 | 已完成训练次数 |
| total_training_seconds | Numeric(10,2) | Not Null | 0.00 | 总训练时长（秒） |
| average_score | Numeric(5,2) | Not Null | 0.00 | 平均分数 |
| best_score | Numeric(5,2) | Not Null | 0.00 | 最佳分数 |
| last_training_at | DateTime(timezone=True) | Nullable | NULL | 最后一次训练时间 |
| created_at | DateTime | Auto-generated | NOW() | 创建时间 |
| updated_at | DateTime | Auto-updated | NOW() | 更新时间 |

### 关系

- **一对一**: user（所属用户）

### 索引

- `user_id` - 唯一索引，确保每个用户只有一条统计记录
- 外键约束：`ondelete="CASCADE"`（用户删除时级联删除统计数据）

---

## 5. admin_logs 表（管理员操作日志表）

记录管理员的所有操作行为，用于审计和安全追踪。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key, Auto Increment | - | 日志ID |
| admin_id | Integer | FK(users.id), Not Null | - | 执行操作的管理员ID |
| action | String(50) | Not Null | - | 操作类型（如：create_user, delete_video） |
| target_type | String(50) | Nullable | NULL | 目标类型（如：user, video, training） |
| target_id | Integer | Nullable | NULL | 目标对象ID |
| details | JSON | Nullable | NULL | 操作详情（JSON格式） |
| ip_address | String(45) | Nullable | NULL | 操作者IP地址（支持IPv6） |
| created_at | DateTime | Default: CURRENT_TIMESTAMP | NOW() | 操作时间 |

### 关系

- **多对一**: admin（执行操作的管理员）

### 索引

- `admin_id` - 外键索引
- `created_at` - 时间索引（便于按时间范围查询）

---

## 6. video_detection_tasks 表（视频检测任务表）

存储视频上传和AI检测任务的状态及结果。

### 表结构

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | Integer | Primary Key, Auto Increment | - | 任务ID |
| uploader_id | Integer | FK(users.id), Not Null | - | 视频上传者ID |
| file_name | String(255) | Not Null | - | 原始文件名 |
| file_path | String(500) | Not Null | - | 文件存储路径 |
| file_size | BigInteger | Nullable | NULL | 文件大小（字节） |
| status | Enum | Not Null | "pending" | 任务状态：pending/processing/completed/failed |
| ai_result | JSON | Nullable | NULL | AI分析结果（JSON格式） |
| error_message | Text | Nullable | NULL | 错误信息（失败时） |
| created_at | DateTime | Default: CURRENT_TIMESTAMP | NOW() | 任务创建时间 |
| completed_at | DateTime | Nullable | NULL | 任务完成时间 |

### 枚举值：status

- `pending` - 等待处理
- `processing` - 处理中
- `completed` - 已完成
- `failed` - 失败

### 关系

- **多对一**: uploader（视频上传者）

### 索引

- `uploader_id` - 外键索引
- `status` - 状态索引（便于查询待处理任务）
- `created_at` - 时间索引

## 数据类型说明

### Numeric 精度

- `Numeric(5,2)` - 最大999.99（用于分数）
- `Numeric(5,4)` - 最大9.9999（用于置信度）
- `Numeric(8,2)` - 最大999999.99（用于时长秒数）
- `Numeric(10,2)` - 最大99999999.99（用于累计时长）

### DateTime

- 所有时间字段均使用时区感知类型 `DateTime(timezone=True)`
- 存储为 UTC 时间

### JSON

- 用于存储结构化但不固定的数据
- 支持嵌套对象和数组
- 数据库层面需要 MySQL 5.7+ 或 PostgreSQL 9.2+

---

## 设计原则

1. **级联删除**: 用户删除时自动清理相关数据
2. **软删除**: 通过 `is_active` 字段实现用户软删除
3. **审计追踪**: 所有关键操作记录到 admin_logs
4. **性能优化**: 常用查询字段建立索引
5. **扩展性**: 使用 JSON 字段存储灵活数据
6. **时区统一**: 所有时间字段使用 UTC 时区

---

## 技术栈

- **ORM**: SQLAlchemy 2.0+（异步模式）
- **数据库**: MySQL / PostgreSQL（可配置）
- **迁移工具**: Alembic（推荐）
- **连接池**: SQLAlchemy 内置连接池
